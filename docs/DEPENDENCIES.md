# Application Dependency & Runtime Manager

Расширение Certificate Inspector (`symport.deps`): что нужно пакету SIS/SISX, и совпадает ли это с выбранным телефоном.
Только **статический** анализ: установка и запуск не выполняются, неизвестное **не считается** установленным или совместимым.

## Что определяется

| Источник | Результат |
|---|---|
| Prerequisites SIS: платформы (`S60ProductID`) | `S60 3rd` (`0x101F7961`, в профиле E52), `FP1` (`0x102032BE`), `FP2` (`0x102752AE`), `S60 5th/Symbian^1` (`0x1028315F`), `Symbian^3` (`0x20022E6D`), `Belle` (`0x2003A678`) — таблица с источниками в `symport/deps/runtimes.py`; принятие E52 для `FP1/FP2` помечено `inferred` |
| Prerequisites SIS: зависимости с именем и диапазоном версий | например `Qt ≥ 4.7.3`; семейство runtime по имени (Qt, Qt Mobility, PyS60, Open C) — эвристика, UID только у Qt (наблюдён в пакете jellyfin-s60v3) |
| Импорты E32 | классификация DLL: внутри пакета / runtime / системная; системные — по данным прошивки, иначе `unknown-no-firmware-data` |
| Capabilities (E32 V) | список и ограниченные (нужен доверенный сертификат) |
| Payload | `.py/.pyc` → подсказка PyS60 (эвристика) |

**Ограничение:** E32-образы внутри SIS обычно сжаты (`bytepair`/`deflate`): их импорты не декодируются, и отчёт говорит
`imports-undecoded`, а не «зависимостей нет». Поэтому надёжнее всего — объявленные зависимости SIS.

## Вердикты

`satisfied-static` · `unresolved` (есть непроверенные требования — обычный исход) · `blocked` (известный конфликт: платформа не
принимается, нужная DLL отсутствует в загруженной прошивке, версия зависимости ниже требуемой). Платформа:
`supported-static` / `unsupported` / `unknown`. Уровни `installation`, `runtime`, `physical_device` всегда `not-tested`.

Данные прошивки: образ из Firmware & ROM Explorer (`firmware_id`) или профиль прошивки Inspector. Без них системные импорты остаются неизвестными.

## Граф и комплект приложения

Граф (пакет → платформы/зависимости/runtime → исполняемые файлы → DLL) выводится в интерфейсе и доступен текстом в таблицах.
**Комплект** (`apps/kits`, действие `bundle`): приложение плюс runtime-пакеты, **которые предоставляет пользователь**, в порядке
установки (топологическая сортировка по объявленным зависимостям; цикл — ошибка). Результат — ZIP `NN-имя.sis`, `manifest.json`
(SHA-256, UID, версии, нерешённое) и `INSTALL.txt`. Неполный комплект (есть нерешённые зависимости) не упаковывается, пока не
разрешён явно; SymPort **ничего не скачивает сам**. Устанавливает пакеты телефон, а не SymPort.

## API

`POST /api/inspector`: `dependencies` (анализ без сохранения; `runtimes: [{source, …}]`, `firmware_id`, `target`),
`bundle` (`allow_incomplete`), а действие `analyze` теперь добавляет в отчёт поле `dependency_analysis`.
