# Firmware & ROM Explorer

Статический просмотр **прошивки, которую загружает пользователь**. SymPort не поставляет, не скачивает и
не распространяет прошивки; файлы лежат на сервере в `build/symport/firmware/<id>/` (права 0700, не больше 6 образов)
до явного удаления. Ничего не запускается, не прошивается и не устанавливается.

## Что можно загрузить

| Вход | Состояние |
|---|---|
| ZIP с распакованным деревом `Z:` (вложенная папка `…/Z/…` допускается: корень определяется по `sys/bin`) | основной режим; разбор на реальных E32/MBM из репозитория и синтетических образах |
| «Сырой» образ core ROM (раскладка `TRomHeader`/`TRomEntry`) | **экспериментально**: проверен только на синтетических образах, собранных тестами; реальной прошивки в среде нет |
| EKA2L1 `.rpkg` v1 (в т. ч. результат конвертера EKA1) | читается только на чтение: индекс файлов, без загрузки в эмулятор; v2 распознаётся и отклоняется |
| Контейнеры Nokia `.fpsx`/`.vpl`, образы ROFS | **не поддерживаются**; распакуйте их отдельным инструментом (например, Symbian Seance) и загрузите ZIP. Файл отклоняется с этим пояснением |

Ограничения: до 1 ГиБ на загрузку (`SYMPORT_FIRMWARE_MAX_MB`), до 200 000 файлов и 8 ГиБ в распакованном виде,
записи ZIP с `..`, абсолютными путями и шифрованием пропускаются и перечисляются. ZIP **не распаковывается на диск**:
файлы читаются из архива по требованию.

## Возможности

* **Дерево `Z:/`** и список файлов папки; **поиск** по пути, типу, UID/SID и capability.
* **Метаданные файла:** размер, SHA-256, UID1–3 (если контрольная сумма UID верна), тип с пометкой основания —
  по заголовку (`magic`) или по расширению (`extension`, в таблице отмечено `*`).
  * **E32 EXE/DLL:** UID, Secure/Vendor ID, capabilities (формат V), версия модуля, ядро/CPU/ABI, сжатие, число экспортов,
    heap/stack, импорты. Сжатые образы (`bytepair`, `deflate`) показывают **только заголовки** — их импорты остаются
    неизвестными и так и помечаются; декомпрессор не реализован.
  * **MBM:** число битмапов и геометрия (проверено на реальных MBM из сборок тем). **MIF:** магия и версия формата
    (внутренний каталог иконок не разбирается). **RSC:** определяется по расширению; содержимое не разбирается.
  * Первые 256 байт — hex.
* **Системные зависимости:** импорты файла сопоставляются с образом (`present-in-image` / `missing-from-image`) и обратная
  связь «кто импортирует этот файл». Для файлов без декодированных импортов зависимости не выдумываются.
* **Сравнение двух прошивок:** добавлено/удалено/изменено/совпадает по SHA-256; для E32 — изменения версии, SID, ядра, CPU,
  сжатия, capabilities и импортов. Списки ограничены (200) с пометкой об обрезке.
* **Профиль прошивки** для Certificate Inspector: имена DLL образа (ординалы экспорта неизвестны, поэтому проверка на
  уровне ординалов остаётся «неизвестно»). Образ можно также выбрать прямо в «Зависимостях и совместимости».

## Что это не доказывает

Наличие файла в загруженной прошивке ничего не говорит о том, что установлено на телефоне, и о том, что прошивка
загрузится. Уровни в отчёте: `static: indexed`, `boot: not-tested`, `physical_device: not-tested`.

## Источники форматов

Структуры ROM сверены с описанием `RomBrowser` (Florin9doi: `TRomHeader`, `TRomEntry`) и публичным `e32rom.h`;
E32-образы разбирает уже имеющийся анализатор SymPort (`symport.analysis.e32`), реализация E32Explorer
(лицензия не указана) **не копировалась**. Код написан заново по описаниям форматов.

## API

`POST /api/firmware` (JSON, токен сессии): `list`, `status`, `children`, `search`, `file`, `dependencies`, `compare`,
`profile`, `delete` (требует `confirm: true`). Загрузка — `POST /api/firmware/upload?name=…&label=…`
(`application/octet-stream`, потоком на диск).


## Прошивки и модификации (CFW Research, #42)

Страница **Инструменты → Прошивки и модификации** (только чтение; ничего не прошивается, не записывается и
не загружается во внешние сервисы).

* **Источники** (`symport/firmware/cfw_sources.json`, проверено 2026-11-05) — только опубликованные авторами данные:
  Reborn Hybrid CFW (alpha) для N95, Reborn CFW для N8/E7 (Belle), Delight CFW (Belle). Для каждого: платформа,
  модели и RM (где автор их не называет — «not stated»), версия/дата, ссылки автора, признанные ограничения,
  статус распространения. Reborn Online Services Bridge — это **веб-конфигурация** (перенаправления URL), а не
  исходники прошивки. Belle-прошивки для E52/E72/N95/N97 mini — `not-applicable`.
* **Инвентарь возможных системных модификаций** по загруженному образу (и необязательному базовому образу):
  найденные URL, SSL/CA, UAProf, автозапуск (`domainsrv`, ROMPatcher, startup), проверка соединения,
  новые/изменённые EXE/DLL/SIS относительно базового образа. Это **зацепки по имени и содержимому**: поведение не
  устанавливается; без базового образа происхождение — `unknown`.
* **Контейнеры:** ZIP — поддерживается; RPKG v1 — чтение; сырой core ROM — экспериментально; `.fpsx`/`.vpl`/ROFS —
  не декодируются (нет проверенной спецификации и образца), расширение никогда не считается признаком совместимости.

## CFW Security Scanner (#46)

Read-only поиск **известных рискованных шаблонов** по версионированной базе
(`symport/firmware/advisories.json`, `db_version` в отчёте). Первая запись — **CVE-2025-65885** (Delight CFW для
Symbian Belle; опубликована 2025-12-26; CVSS v3.1 5.1 MEDIUM по CISA ADP, CWE-77; затронуты 11 моделей из текста CVE
и ещё C6-01 только по описанию исследователя). Поле `platform` прямо говорит, что это не E52/E72/N95. Утверждения
исследователя (в т. ч. «critical» и поведение механизма) помечены как слова автора, SymPort их не проверял и
ничего не эксплуатирует.

Правила: ссылка на `Delight.txt` в бинарнике/данных, ссылка на текстовый файл в `X:\Data` перезаписываемого
диска (доверие к изменяемому пути), упоминание `domainsrv` (информационно). Файлы не запускаются, ограничения:
файл ≤ 32 МиБ, ≤ 20000 файлов, ≤ 512 МиБ суммарно, 120 с. Сжатые E32-образы и слишком большие файлы попадают в
`not_tested`. Версию CFW/модели вы **заявляете сами**; совпадение с перечнем затронутых версий даёт
`vulnerable-version (declared by you; not verified from the image)`.

Вердикт: `vulnerable-version` / `suspicious-pattern` / `no-pattern-found` / `unknown` / `not-tested`; у каждого
совпадения — путь, SHA-256, смещение, правило и оговорка о надёжности. **`no-pattern-found` не доказательство
безопасности** (`proof_of_safety: false`, покрытие указано). Карточка уведомления показывается в источнике CFW до
установки. Ложные срабатывания возможны (например, текст, упоминающий имя файла).

## EKA1 ROM → RPKG (#47, экспериментально)

Отдельный конвертер для **ваших** дампов старых ROM EKA1 (база `0x50000000`) в `.rpkg` v1 для EKA2L1/MGO. Это не
EKA2 и не поддержка E52/E72/N95. Реализован по публичному описанию структур (формат RPKG v1 и раскладка core ROM),
**не копирует код** сторонних утилит; референс идеи — `symbuzzer/rom2rpkg` (GPL-3.0). Ограничения: ROM ≤ 48 МиБ,
таймаут 60 с, имена проверяются (без `..`, разделителей), нулевые файлы и каталоги не пишутся, записи пишутся
потоково. Отчёт и RPKG выгружаются отдельно. Статусы: `converted` / `accepted-by-emulator` / `booted` /
`unsupported` — конвертер выставляет только `converted` или `unsupported`; `accepted-by-emulator` и `booted`
остаются `not-attempted` / `not-tested`, пока агент реально не поддерживает такой профиль (передача в MGO не
выполняется). Проверено только на синтетических образах: реальный EKA1-дамп — `not-tested`, о чём сказано в
отчёте. Существующий импорт EKA2 core ROM не изменён.
