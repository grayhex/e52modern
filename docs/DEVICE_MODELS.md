# Модели телефонов Nokia S60 (реестр)

Интерфейс и бэкенд не содержат «зашитых» E52/E72: изображения, геометрия экрана и профили
инструментов берутся из **реестра моделей** `symport/phone/device_models.json`. Новая модель
добавляется данными.

## Что получает пользователь

| Модель в реестре | Модель только в `S60_MODELS` | Не S60 / неизвестная |
|---|---|---|
| имя, S60/Symbian, геометрия экрана, ввод, картинка; профиль для каталога и редактора тем | имя и редакция S60/Symbian; **без картинки и геометрии** — показывается обобщённый контур с подписью «нет изображения для этой модели» | профиль не выдаётся |

Редакция S60 → Symbian: 3rd → 9.1, 3rd FP1 → 9.2, 3rd FP2 → 9.3, 5th → 9.4 (документированные
соответствия, не измеряются на телефоне). Ничего не выдумывается: у модели без записи нет ни
фотографии, ни размеров экрана.

## Как добавить телефон

1. **Редакция.** Убедитесь, что модель есть в `S60_MODELS` (`symport/phone/models.py`) — это справочник
   документированных моделей и их редакций S60. Добавьте, если нет.
2. **Реестр.** Добавьте запись в `symport/phone/device_models.json`:

   ```json
   {
     "id": "nokia-e71", "model": "E71", "name": "Nokia E71", "family": "Eseries",
     "image": "/phones/nokia-e71.png",
     "screen": {"width": 320, "height": 240, "orientation": "landscape"},
     "input": "qwerty", "toolchain_profile": null,
     "source": "https://… (откуда взяты данные)"
   }
   ```

   `image` и `screen` можно опустить (`null`), пока нет ресурса/подтверждённых данных.
   Загрузка строгая (`load_registry`): неизвестные поля, дубликаты `id`, пути вне `/phones/*.{png,webp,svg}`,
   нереалистичная геометрия или модель вне `S60_MODELS` — ошибка, а не частичная загрузка.
3. **Картинка (необязательно).** PNG с прозрачным фоном в `symport/web_assets/phones/<имя>.png`
   (и `frontend/public/phones/`); в README этой папки укажите происхождение изображения. Сервер отдаёт изображения с безопасными именами PNG/WebP/SVG.
4. **Профиль инструментов (необязательно).** `profiles/<id>.toml` с источниками каждого значения; затем
   укажите `"toolchain_profile": "<id>"` — модель появится в списках «Целевой профиль» каталога и
   «Профиль экрана» Theme Studio. Без профиля модель получает идентификацию и картинку, но не выбирается
   как цель сборки.
5. **Тесты.** `tests/test_device_models.py` проверяет реестр; дашборд и мастер подключения не требуют правок.

## Где модель используется

`DeviceManager.discover` отдаёт `models` (реестр) и `model_profile` для каждого подключения
(`presentation()`); React берёт отсюда картинку героя дашборда, подпись геометрии, варианты иллюстрации
для неопознанного телефона, списки целей каталога/Theme Studio и размеры предпросмотра темы.
Классический интерфейс и CLI-профили (`profiles/*.toml`) живут отдельно и подключаются через `toolchain_profile`.

## N95 / N95 8GB

Реестр расширен полями aliases/rms, target_model, artwork, platform_uids и статусами фактов.
Они описывают модель, не capabilities подключения. Обычное `N95` остаётся семейным
профилем без toolchain_profile; варианты выбираются по суффиксу/RM. Геометрия иллюстраций
и экранов общая для Python и React. Подробнее: [NOKIA_N95.md](NOKIA_N95.md).

## N97 mini: отдельная модель и инструменты

`nokia-n97-mini` имеет собственные aliases, `exact_aliases`, `screen_modes` и native platform UID.
Наиболее специфичные имена распознаются раньше `N97`; неподтверждённые suffix/RM не угадываются.
`image` указывает на отдельный реалистичный корпус N97 mini с прозрачным фоном; `artwork` остаётся
null, поскольку декоративное изображение не включает preview тем или эмуляторный экран.
`theme_studio.status=unsupported` — свойство инструмента, не транспортная capability. Mini
остаётся целью Inspector/каталога/наборов, но не входит в `theme_profiles()`; backend и worker
не могут запустить для неё пайплайн S60 3rd. [Описание](NOKIA_N97_MINI.md).
