# Резервная копия, инвентарь и передача файлов (командная строка)

Все команды работают с **смонтированным томом** (карта памяти E52 в режиме «Mass storage» или картридер): каталог на
вашем ПК. Директория сама по себе не доказывает, что подключён телефон; SymPort ничего не пишет на том без явной команды.

```bash
symport phone backup create --volume /media/user/E52 --dest ~/backups/e52-2026-11-03 --label e52-card
symport phone backup verify ~/backups/e52-2026-11-03
symport phone backup restore ~/backups/e52-2026-11-03 --volume /media/user/E52          # план (dry run)
symport phone backup restore ~/backups/e52-2026-11-03 --volume /media/user/E52 --apply  # запись новых файлов
symport phone apps inventory --volume /media/user/E52
symport phone stage build/symport/theme/light/e52clearlight.sis --volume /media/user/E52   # → Installs/
symport phone calendar read --gammu-config ~/.gammurc                                      # нужен Gammu
```

Каждая команда поддерживает `--json` / `--report FILE` (формат `symport.report/1`).

## Полная резервная копия

* Рекурсивно, **потоково** (не держит файлы в памяти), с SHA-256 каждого файла; mtime сохраняется.
* Каталог копии: `manifest.json` (схема `symport.backup/1`, размеры, хеши, пропущенное), `manifest.sha256` (защита манифеста),
  `files/…`. Абсолютный путь источника не записывается — только `--label`.
* Не следует по symlink, пропускает не-обычные файлы и фиксирует это в манифесте и отчёте. Пропущенное ⇒ копия **неполная**
  (`complete: false`), команда предупреждает; `--exclude REL` пропускает путь по запросу.
* Отказывается писать в непустой каталог, внутрь источника, при нехватке места (запас 5 %), при превышении лимитов
  (по умолчанию 200 000 файлов / 64 ГиБ). Файл, изменившийся во время копирования, не попадает в манифест.
* После создания копия сразу перечитывается и проверяется по хешам. `verify` ловит повреждение, пропажу, лишние файлы и
  подмену манифеста.

**Это файловая копия.** В неё не входят контакты, SMS, календарь, реестр установленных приложений в памяти телефона и
прошивка. Для контактов и календаря есть отдельные команды/раздел «Контакты».

## Восстановление

* По умолчанию — **план**: `new` / `identical` / `conflict` / `blocked`. `--apply` пишет только `new`.
* **Никогда не перезаписывает** существующие файлы и ничего не удаляет; конфликтующие остаются нетронутыми.
* Перед записью заново проверяет копию; после записи сверяет хеш каждого файла чтением обратно.
* Пути из манифеста проверяются теми же правилами, что и в Device Manager (без `..`, абсолютных путей, `:`, зарезервированных
  имён); подделанный манифест не может выйти за пределы тома.
* `--only Images` восстанавливает один путь/папку.

## Инвентарь SIS

Перечисляет `.sis/.sisx` на томе: имя, UID (с классом диапазона), версия, вендор, подпись, число файлов, контрольные суммы,
дубликаты UID. **Установленное состояние на телефоне с тома не наблюдаемо** — отчёт помечает его как `unknown`.

## Передача SIS без SDK

`phone stage` проверяет SIS (структура и CRC), предупреждает о неподписанном пакете, копирует в `Installs/` (имя из
документации symbian-platform; меняется `--folder`), не перезаписывает существующее и сверяет SHA-256. Это **передача файла**:
установку подтверждает только телефон (чек-лист в [DEVICE_TEST.md](DEVICE_TEST.md)).

## Календарь и задачи (Gammu, только чтение)

`gammu backup <файл>.ics -yes` пишет стандартный iCalendar (календарь и задачи — по документации `gammu`). SymPort разбирает его
(`vobject`) и выводит события и задачи. Пустой экспорт считается **неоднозначным** (нет записей или нет поддержки), а не успехом.
Поддержка E52 в Gammu не подтверждена; на телефон ничего не пишется. Тот же код доступен через API Device Manager
(`calendar-read`, при настроенном `SYMPORT_GAMMU_CONFIG`).

## Статус проверки

Автотесты (`tests/test_phone_*.py`) выполняют все операции на реальных временных каталогах и с поддельным `gammu`: повреждённые и
подменённые манифесты, небезопасные пути, symlink, нехватка места, конфликты, обрыв. **Ни одна операция не выполнялась с
физическим E52.** Поведение настоящей карты (FAT32, имена, длинные пути, отключение посреди копирования) нужно проверить вручную.
