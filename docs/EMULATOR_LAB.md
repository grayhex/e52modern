# Emulator Lab: EKA2L1 через MGO

Lab использует готовый `mgo-symbian` из [grayhex/MGO](https://github.com/grayhex/MGO).
SymPort предоставляет интерфейс, выбор пакетов, подтверждения и постоянные отчёты;
агент MGO запускает EKA2L1, устанавливает прошивки/SIS, передаёт ввод и снимки экрана.
Код эмулятора и агента в E52Modern не копируется. CLI `emulator list/test` сохранён
как отдельный, настраиваемый оператором адаптер: [EMULATOR.md](EMULATOR.md).

## Запуск

Требуются Linux Docker/Compose v2, amd64, около 3 ГиБ RAM для эмулятора и свободный
диск под образы, распакованную прошивку и отчёты. Образ использует программный
рендеринг, GPU и подключённая физическая Nokia не нужны для запуска сервиса.

```bash
docker compose --profile emulator up -d --build
# На своём ПК, если Docker на удалённом сервере:
ssh -L 8765:127.0.0.1:8765 user@your-server
# Браузер: http://127.0.0.1:8765/#lab
```

Без профиля `emulator` остальные разделы работают, Lab показывает недоступность.
Образ MGO закреплён по digest в `compose.yaml`:

- `ghcr.io/grayhex/mgo-symbian@sha256:83e62c6737a1cdcdf992bd8d3803738ff6a73b278a71118e69318446db4789cc`;
- версия внутри: `EKA2L1 master-e04eb03+mgo-vpl2`;
- сверенный контракт агента: MGO [`872f449719a40c80d5dfab4400f0736325828230`](https://github.com/grayhex/MGO/tree/872f449719a40c80d5dfab4400f0736325828230/symbian);
- EKA2L1 [`e04eb030653d185483a44f0394d42a319ad334f2`](https://github.com/EKA2L1/EKA2L1/tree/e04eb030653d185483a44f0394d42a319ad334f2)
  с существующими патчами MGO для VPL/FPSX.

MGO распространяется под MIT, EKA2L1 — GPL-3.0; исходники, патчи и сборка доступны
в указанных проектах. Закрепление версии проверяет API, а не совместимость E52.
При обновлении digest повторите contract-тесты и проверку на собственной прошивке.

## Пользовательская прошивка

1. Откройте **Emulator Lab → Ваша прошивка**. Выберите один формат:
   **ROM + необязательный RPKG**, **архив** поддерживаемого EKA2L1 формата или
   **один VPL + связанные FPSX**. Проприетарных файлов в Git и образе SymPort нет.
2. Для VPL сохраните исходные имена и регистр компонентов. Загрузка создаёт новый
   bundle; файлы должны принадлежать одному комплекту. Если в VPL несколько
   вариантов, укажите индекс с нуля. Произвольный FPSX без VPL не устанавливается.
3. **Загрузить файлы** передаёт байты через защищённый backend потоком, с прогрессом
   и SHA-256. Лимит — 2 ГиБ на файл, VPL — 4 МиБ, комплект — до 128 файлов.
4. Выберите загруженный комплект → **Установить прошивку** → подтвердите остановку
   текущего сеанса и установку. Ждите завершения задания, смотрите ошибки/логи в отчёте.
5. После успешной установки выберите устройство из фактического списка MGO и
   нажмите **Запустить**. Выбор сохраняется как Symbian default в MGO.

Список отражает **устройства, установленные в EKA2L1**, а не найденные телефоны.
Модель/код читаются из MGO; E52 не присваивается по имени загруженного файла.
Прошивка другого телефона не превращается в E52 из-за размера экранной рамки.
Не любой комплект E52/RM-469/родственной модели поддерживается EKA2L1. При ошибке
читайте `agent_job.errorCode`, журнал и ограничения, не повторяйте установку вслепую.

MGO использует временные входные файлы и удаляет комплект после принятого задания,
включая неуспешную установку. Такие записи помечены «использован»: для повторной
попытки загрузите исходные файлы снова. **Установленные** прошивки сохраняются в
постоянном томе; их оригиналы нужно также хранить у себя.

## Виртуальный телефон

Корпус — детальная серебристая Nokia E52 по фотографическому референсу, с отдельными
зонами реальных клавиш. Это иллюстрация, не подключённое устройство. Клавиша Почта
недоступна в API, Clear вынесена отдельно.

Экран — реальный PNG `/v1/screenshot?region=guest`, 240×320 для E52, размещаемый в измеренном окне корпуса
с сохранением пропорций. Фактическое разрешение указано под экраном. Без активной
поверхности выводится причина EKA2L1; демонстрационных экранов в приложении нет.
Обновление изображения — до 4 раз/с, опрос состояния — раз в 2,5 с.

Кликните телефон для фокуса клавиатуры. Поддерживаются стрелки, Enter/OK, F1/F2
(softkeys), F3 (`applications`, системное меню), Backspace, Escape/отбой, цифры,
`*` и `#`. Удержание передаёт `down/up`; потеря фокуса/смена вкладки освобождает
клавиши. Кнопки, отсутствующие в списке EKA2L1, недоступны. `menu` API является
алиасом левой softkey и намеренно не используется для системного меню.

**Перезапуск** останавливает и заново создаёт сеанс MGO. **Стоп** завершает его.
MGO также ограничивает сеанс двумя часами. C:/E: сохраняются через механизм saves
MGO: отдельный постоянный saveKey для каждого кода прошивки, общий между тестами
на этой прошивке. Установка тестового SIS меняет этот виртуальный телефон.
Не загружайте туда личные контакты и учётные данные без необходимости.

Системное меню, shell, применение тем, отдельные аппаратные API и онлайн-службы
зависят от прошивки/EKA2L1. Их наличие не гарантируется. Звук и сенсорный ввод
в интерфейсе SymPort пока недоступны. Контейнер гостя находится во внутренней сети;
онлайн-приложения могут не работать.

## Приложения, игры и темы

**Проверить в эмуляторе** доступно в каталоге, локальной библиотеке тем и списках
собранных SIS. Либо выберите свой SIS/SISX до 32 МиБ непосредственно в Lab.
Действие только выбирает сценарий: установку нужно подтвердить отдельно.
Каталог использует существующий downloader с закреплёнными размером/SHA-256;
для ручных/лицензионных загрузок сначала скачайте пакет по ссылке автора,
затем выберите файл в Lab. Ограничения лицензии не обходятся.

Для приложения SymPort проверяет структуру SIS, сохраняет исходные байты и hash,
загружает пакет в MGO, вызывает реальный установщик и определяет приложение по
результату установки/изменению реестра. При неоднозначном UID установка остаётся
`installed`, запуск — `not-tested`; программа не выбирается наугад.
Только ответ сеанса `running` даёт `launched`; `launching` таким успехом не считается.

Для **E52 CLEAR и других тем** выберите сценарий **Тема**. Собранные темы и пакеты
из библиотеки автоматически используют его; skin-пакеты без EXE также определяются
по install targets. **UID темы никогда не запускается**. После установки откройте
системное меню → Средства/Параметры → Темы → Общие, примените тему вручную.
Названия и доступность меню зависят от прошивки. Отметьте применение, главный экран,
меню, списки и диалоги кнопкой **Записать наблюдение + снимок**. Это явно отмеченные
наблюдения пользователя. При отсутствии меню/службы выберите `unsupported`;
успешная установка не подтверждает применение темы.

**JAR/JAD:** этот агент MGO не предоставляет установку Symbian Java ME. Lab фиксирует
`unsupported`, `engine: not-run`, без установки, запуска и чужих снимков. Отдельное
ядро **KEmulator** в MGO не является Symbian Java ME и здесь не подключается под
видом проверки на E52. Передача Java-пакета на Nokia доступна в Device Manager.

## Отчёт и передача на Nokia

Каждая операция получает JSON `symport.emulator-lab/1`: пакет/источник/размер/SHA-256,
прошивка, версия движка, этапы, свидетельства установки/запуска, ошибки, логи,
метаданные снимков (hash, размер, время), ручные наблюдения и ограничения.
JSON и PNG скачиваются отдельно из отчёта. История сохраняется при перезапуске;
показаны последние 50 операций. Незавершённая операция после рестарта backend
помечается `not-tested`, автоматически не повторяется.

| Статус | Свидетельство |
|---|---|
| `installed` | Установщик MGO/EKA2L1 успешно завершил установку |
| `launched` | EKA2L1 подтвердил `running` приложения |
| `failed` | Операция/запуск завершились ошибкой |
| `unsupported` | Функция/формат не доступны, причина сохранена |
| `not-tested` | Нет результата проверки; отдельный запуск сеанса не проверяет ПО |

После подтверждённой установки SIS отчёт открывает **Передать на телефон**.
Выберите накопитель/PC Bridge и путь, подтвердите копирование. SymPort повторно
сверяет SHA-256 сохранённых байтов и вызывает существующий Device Manager.
Результат — `transferred-not-installed`; установка на Nokia всегда проверяется
отдельно. [Подключение Windows/удалённого сервера](DEVICE_MANAGER.md).

## Хранение и защита

- `mgo-symbian-data` → `/data`: прошивки, staging и saves существующего агента MGO.
- `mgo-symbian-auth` → `/symbian-auth`: генерируемый MGO bearer key, backend читает
  том read-only. Ключ не отправляется в браузер, URL, отчёт или Git.
- `symport-build` → `build/symport/emulator-lab`: отчёты, исходные тестируемые пакеты,
  PNG и ledger загрузок с SHA-256. Каталоги данных закрыты правами `0700`.

`docker compose down` / обновление образов сохраняют именованные тома.
`down -v` их удалит. Резервируйте тома при остановленных сервисах. Исходные ROM и
экспортированные результаты содержат пользовательские данные: не коммитьте их.

У `mgo-symbian` нет опубликованных портов и нет внешней сети; EKA2L1 слушает только
loopback внутри контейнера. Агент MGO требует bearer key и фильтрует control routes.
SymPort добавляет собственный allow-list операций, проверяет Host/Origin и session
CSRF token. Универсального прокси к `/v1/files`, конфигурации или путям хоста нет.
Workbench доступен только на `127.0.0.1:8765` через SSH-туннель. Это локальная
однопользовательская среда, не публичный многопользовательский сервис: не меняйте
bind на публичный интерфейс без отдельной аутентификации.

Для запуска Python-backend рядом с контейнером оператор может задать
`SYMPORT_MGO_URL` (`mgo-symbian` внутри Docker либо `127.0.0.1`/`localhost` локально)
и `SYMPORT_MGO_TOKEN_FILE`. Для тестового процесса доступна `SYMPORT_MGO_TOKEN`;
в Compose используется файл. Произвольные URL из запросов браузера не принимаются.

## Проверки без телефона и ROM

```bash
pip install -e '.[dev]'
pytest tests/test_emulator_lab.py
node tools/check_emulator_lab.cjs  # нужен Playwright Chromium, см. CI
```

Успешный end-to-end сценарий (браузер → backend → MGO HTTP contract → отчёт → том
телефона) проверяется **mock-агентом**, включая загрузку прошивки, кнопки, SIS,
тему без UID launch, каталог/игры, библиотеку/сборки и передачу тех же байтов.
Эти результаты не являются запуском приложения/темы в настоящем EKA2L1.

Для **настоящего закреплённого контейнера MGO** используйте отдельный пустой проект:

```bash
docker compose build workbench
docker compose -p symport-lab-smoke --profile emulator up -d mgo-symbian
docker compose -p symport-lab-smoke run --rm -T --no-deps workbench python tools/check_mgo_runtime.py
# Только для этого одноразового проекта, без пользовательских данных:
docker compose -p symport-lab-smoke --profile emulator down -v
```

Smoke проверяет настоящий maintenance-запуск EKA2L1, доступные клавиши/capabilities,
отсутствие guest-screen без ROM и реальный отказ VPL-парсера на синтетических
невалидных данных. Скрипт отказывается работать с установленной прошивкой.
Собственная прошивка E52, успешный boot, установка/запуск реального SIS, применение
темы и работа на физической Nokia **ещё не проверены**. Именно этот этап требует
вашего комплекта и ручного протокола.
