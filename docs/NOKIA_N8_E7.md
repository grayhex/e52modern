# Nokia N8-00 / E7-00

N8 и E7 — отдельные цели SymPort из семейства **Symbian^3**. Установленная ОС может быть
Symbian^3, Anna, Belle или Belle Refresh: **модель, номер прошивки и выбор CFW не назначают Belle
автоматически**. Телефонные проверки обеих моделей: `physical_device: not-tested`.

| | N8-00 | E7-00 |
|---|---|---|
| RM | RM-596 | RM-626 |
| Экран | 360×640, поворот 640×360 | 360×640, поворот 640×360 |
| Управление | Сенсорное | Сенсорное и выдвижная QWERTY |
| Память по спецификации | Внутренняя mass memory 16 ГБ и microSD | Внутренняя mass memory 16 ГБ; microSD нет |
| Смонтированные тома, свободное место | Только из фактического подключения | Только из фактического подключения |

Профили `profiles/nokia-n8.toml` / `nokia-e7.toml` сохраняют source/status каждого факта.
RM взяты из [задачи #68](https://github.com/grayhex/s60modern/issues/68), с `status: stated`;
общие характеристики — из [N8](https://en.wikipedia.org/wiki/Nokia_N8) / [E7](https://en.wikipedia.org/wiki/Nokia_E7).
Имена `N8`, `N8-00`, `E7`, `E7-00` нормализуются без смешивания E7/E72. Конфликтующие RM и
неподтверждённые суффиксы не выбирают профиль. Product code хранится как наблюдение, не как
непроверенная таблица регионов. Текущие ОС, прошивка, права и показания остаются неизвестными
до отдельного ответа адаптера; для версии ОС нужен также источник.

## Первое USB-подключение

1. Установите текущий SymPort. Для Windows используйте **Bridge 0.3.2 или новее** из проверенной
   сборки проекта; браузер связывается с ним через существующий мастер подключения. Linux
   использует те же адаптеры. Docker на сервере не видит USB вашего Windows-ПК напрямую.
2. На телефоне откройте **Параметры → Подключение → USB**; названия зависят от версии ОС.
   Для файлов выберите **Накопитель / Mass storage**. Дождитесь появления реального тома в ОС.
3. Откройте «Подключение», затем «Файловый менеджер», выберите обнаруженный том. На N8
   внутренняя память и карта могут быть отдельными томами. На E7 не создаётся выдуманная microSD.
4. Скачайте небольшой файл. Подтвердите передачу тестового SIS в публичную папку, затем
   скачайте его обратно и сравните SHA-256. Уже существующий файл не заменяется.
5. Безопасно извлеките том в ОС. Отключите USB/смените режим перед ручным открытием SIS на
   телефоне, если подключение ограничивает доступ к памяти. **Передано ≠ установлено.**

Windows Bridge использует существующие Nokia USB/CIM associations, включая fixed USB volumes;
системный диск исключён. Drive letter, ёмкость и USB friendly name не становятся идентификацией
телефона. На Linux явно задайте только корень нужного смонтированного тома. Не подключайте
весь `C:` или корневую файловую систему ПК.

Источники режимов USB: [N8 manual](https://nokia-n8-00.helpdoc.net/en/nokia-n8-00-user-guide/connectivity/usb-data-cable/change-the-usb-mode/),
[E7 guide](https://device.report/m/ad81da13945c7f8798c6f2c94eb1a63e6c7a82122c354dd06603b095b8b822ae.pdf).
Эти зеркала вернули HTTP 403 при исследовании 2026-11-06; инструкции требуют проверки на
телефоне, а не трактуются как выполненный аппаратный тест. Доступные зеркала руководств:
[N8](https://www.manua.ls/nokia/n8/manual), [E7](https://www.manua.ls/nokia/e7/manual).

## Возможности подключения

| Транспорт | Что реально используется | Ограничения |
|---|---|---|
| USB Mass Storage | Существующий MountedVolumes: файлы, медиагалерея, рингтоны, vCard-файл, копирование SIS/JAR, файловые копии | Только видимый том. Нет PIM/батареи/IMEI/внутреннего C: из факта монтирования |
| Nokia / Ovi Suite USB | Nokia-драйвер, реальный serial endpoint, существующий Gammu probe | Suite может занимать порт: закройте его перед пробой. AT/modem reply не доказывает PIM или файловый доступ |
| Gammu USB / Bluetooth | Тот же libGammu backend, фактический ответ идентификации и отдельный status каждого PIM-хранилища | Проверенного драйвера/версии ОС N8/E7 здесь нет; отсутствующие функции получают причину, а не успешный пустой список |
| Gammu S60 Remote | Отдельная добровольная установка совместимого applet/runtime пользователем | PyS60/applets не считаются предустановленными или совместимыми с Belle; ничего не скачивается и не устанавливается автоматически |
| Bluetooth OBEX FTP | Действительно найденный SDP FTP service и доступный ObexFTP | Только namespace сервера; файловая запись требует подтверждения и read-back |
| Bluetooth OPP | Явно выбранный адрес и service | Только push. Нет browse/PIM/read-back и подтверждения установки |

На Windows ObexFTP не поставляется внутри Bridge. Наличие Nokia Suite не означает наличие
автоматического backend для полного Suite-протокола. Общие GPL/CLI/license boundaries сохранены:
[TRANSPORTS.md](TRANSPORTS.md). В аудированной таблице моделей Gammu не найдено отдельного
верифицированного N8/E7 backend; новый протокол не создавался. Тестовые ответы драйвера проверяют
маршрутизацию, не аппаратную совместимость.

Capabilities остаются `available / not-tested / unsupported / error` с evidence. Подтверждения,
PIM-предпросмотры и приватные строки сбрасываются при смене профиля, USB-режима, телефона или
идентичности тома. Записи в `sys`, `private`, `resource`, `system` корня тома закрыты;
обход путей, симлинки, перезапись и запись без подтверждения не разрешаются.

## Приложения и версии ОС

- Общий Product UID **0x20022E6D** описывает семейство Symbian^3.
- **0x2003A678 (Belle)** принимается статически только при отдельно указанной Belle/Belle Refresh.
  При неизвестной ОС результат `unknown`; Anna не считается Belle.
- S60 3rd/FP1/FP2/5th-only prerequisites не получают автоматического одобрения. Несколько UID
  рассматриваются как альтернативные цели по существующим правилам SIS.
- Qt/Qt Mobility, версии DLL, capabilities, сертификаты и точная прошивка проверяются отдельно.
  Из модели не следует установленная Qt. ARMv6 на этих целях остаётся непроверенным ABI,
  а не автоматически наследует отказ профилей S60v3 или обещание запуска.
- В Inspector поле Symbian оставьте пустым, пока ОС неизвестна. При наличии сведений укажите
  `^3`, `Anna`, `Belle` или `Belle Refresh`; это явная цель анализа, не результат чтения телефона.
- Каталог и наборы имеют отдельные статусы N8/E7. Проверки E52/E72/N95/N97 mini не наследуются.

Галерея, обработка медиа, резервные копии и перенос пакетов используют существующие функции.
Медиапресеты и размеры обоев учитывают экран; экспорт или передача не подтверждают воспроизведение
и назначение рингтона на устройстве. Файловая копия не является полным системным backup.

## Reborn / Delight: подготовка, не прошивальщик

В режиме разработчика откройте **Кастомные прошивки**; Revive также предлагает переход для N8/E7.
Используются существующие карточки авторов и Firmware Explorer.

1. Выберите модель, источник и реальное подключение. Откройте ссылку автора и получите файл вручную.
2. Для просмотра содержимого загрузите свой **распакованный ZIP Z:** / core ROM в Firmware Explorer.
   FPSX/ROFS не декодируются; один VPL не является прошивкой и не доказывает подлинность файлов.
3. При наличии загрузите небольшой **VPL до 512 КиБ** в форме подготовки. Парсер извлекает RM,
   SW version, product code и явно присутствующие язык/раскладку, сохраняет SHA-256. DTD/entities,
   неверный формат и конфликтующие значения отклоняются. Отсутствующее остаётся неизвестным.
4. Сверьте точную версию и вариант. На E7 язык интерфейса не подтверждает физическую QWERTY:
   проверьте раскладку. Ручные поля имеют статус user-declared. Несовпадение RM/известного product
   code и отсутствие раскладки E7 блокируют подготовку. Изменение формы скрывает устаревший отчёт.
5. Прикрепите проиндексированный образ: его фактический SHA-256 включается в JSON-отчёт. Сохраните
   резервные копии важных файлов/PIM и сведения об отдельной проверенной процедуре восстановления.

Автор [Reborn](https://avalibeyaz.com/s3/reborn.htm), просмотрено 2026-11-06, указывает **N8 v20260912**
и **E7 v20260308**, основу Belle Refresh и варианты E7 **Euro1GenericWorld / Turkish / Russian**.
Это метки релиза CFW; точный stock firmware/RM/product code автором не указан. Языки различаются
между сборками, а не образуют одну универсальную прошивку. [Delight](https://www.symwld.com/delight/)
потребовал browser verification: точные текущие версии/раскладки не подтверждены. Существующее
уведомление CVE показывается отдельно и не является полным сканированием безопасности.

Отчёт остаётся `research-only` или `blocked`; `flashing: unsupported`. Нет кнопки прошивки,
загрузки ROM в Git/образ, записи системных файлов, Phoenix/BEST, jailbreak или обещания полного отката.
N95 Reborn SIS wizard не используется для этих Belle CFW. Theme Studio для N8/E7 также закрыт:
ни импорт, ни сборка, ни live preview Belle-тем текущим компилятором не выполняются.

## Ручная приёмка на устройстве — не выполнена

1. Записать модель/RM, фактическую прошивку, ОС и драйвер; скрыть IMEI и приватные данные.
2. Пройти USB Mass Storage: подтвердить каждый реальный том, маленький upload/download/SHA,
   запрет перезаписи/системного пути и отключение. N8: проверить карту отдельно; E7: не ждать microSD.
3. Просмотреть фото, скачать музыку, экспортировать файловый backup и сделать restore-preview в пустую папку.
4. Проверить Suite mode с корректным драйвером, занятый порт и отдельные PIM status calls;
   экспортировать доступные записи. Не отправлять SMS и не записывать PIM без соответствующих подтверждений.
5. Проверить Bluetooth SDP/OPP/FTP отдельно; не превращать имя спаренного устройства в идентификацию.
6. Переключить режим USB, том и профиль; старые capabilities, планы и приватные строки должны исчезнуть.
7. Проанализировать benign Symbian^3 SIS, Belle-only SIS при неизвестной/явной ОС и S60v3-only SIS.
   После передачи вручную зафиксировать отдельно установку и запуск на телефоне.
8. Проверить подготовку Reborn/Delight, неправильный RM и раскладку E7. Убедиться, что Theme Studio и flashing недоступны.

Автотесты используют реальные временные host volumes, HTTP API, кодировщики/обработку файлов и
явные doubles телефонного драйвера. Они не равны подключению физического N8/E7.
