# SymPort — Nokia Classic Design System

> **Статус:** дизайн-спецификация для реализации. **Целевая эпоха:** Nokia Eseries / S60 3rd Edition FP2, приблизительно 2008–2010. **Область:** веб-интерфейс SymPort из репозитория [`grayhex/s60modern`](https://github.com/grayhex/s60modern), а НЕ прошивка телефона и НЕ собираемая тема E52 CLEAR. **Версия документа:** 1.0, 2026-11-04.

## 1. Задача и визуальный характер

Перевести весь веб-интерфейс SymPort из Nimbus в единый **Nokia Classic**: узнаваемая фирменная эстетика Nokia времён E52/E71/E72, функциональная плотность Nokia PC Suite / Ovi Suite и деловая аккуратность Eseries. Сделать ощущение «современного, но настоящего инструмента Nokia из 2009 года», а не старой веб-страницы с ограничениями 2009 года.

**Ключевой принцип:** историческая узнаваемость в цвете, логотипе, пропорциях, иконографике, навигации и состояниях; современная доступность, масштабируемость и производительность. Это **современная адаптация**, а не буквальное копирование пикселей S60 на экран компьютера.

### Обязательные критерии узнаваемости

1. На первый взгляд видно **классический синий NOKIA `#124191`**, белый, прохладные серебристо-серые плоскости и аккуратные разделители.
2. Используется **классическая сплошная форма букв NOKIA до 2023 года**. Новый «разорванный» логотип 2023 года, Nokia Lumia/Windows Phone Metro и его типографика исключены.
3. Компактная, спокойная рабочая оболочка: ясные панели, список устройств, файловые таблицы, индикаторы подключения, явные подписи, не «финтех-дашборд».
4. Мотивы старого S60: функциональные иконки, выделение строки синим, чёткая иерархия «выбрано / доступно / недоступно», сдержанные статусные панели. **Не копировать софт-клавиши или экран 240×320 в desktop UI**.
5. Фирменность не мешает работе: контраст, клавиатура, RU/EN, мобильная адаптация, настоящие данные устройства, состояния ошибок и безопасность сохраняются.

### Чего не делать

- Никаких абстрактных букв **N O K I A** в стиле брендинга 2023+, не использовать сверхяркий `#005BFF` как главный брендовый цвет.
- Не переносить палитры «Trust, Love, Keep» 2021 года целиком: это материал более поздней эпохи, а не доказательство UI-палитры E52.
- Не превращать интерфейс в Windows XP, S60-эмулятор, Windows Phone 7/8, Fluent или Material Design.
- Не использовать огромные 16–24 px скругления, pill-кнопки повсюду, бирюзовый неон, масштабные bento-карточки, glassmorphism, тяжёлые тени, сплошной тёмно-синий фон, «hero» на половину экрана.
- Не применять зелёный/cyan в качестве основных действий. Зелёный оставить статусом успеха или подключённого устройства.
- Не добавлять бессмысленные декоративные контуры телефонов в каждом разделе.

## 3. Цветовая система

| Токен | HEX | Назначение |

| `brand-pressed` | `#0B2B63` | Pressed/active |

**Правило распределения:** ~75–85% светлые и нейтральные поверхности, ~10–20% текст и границы, ~5–10% Nokia Blue. Синий — сигнал действия и идентичности, а не заливка всего интерфейса. Остальные исторические разноцветные иконки — локально и экономно.

### Тёмная тема (сохранить, но не делать основной)

Исторический S60 имел различные темы, поэтому тёмный режим **допустим как современная производная**, но он не является историческим эталоном бренда. Поддерживать существующие значения `system`, `light`, `dark` и текущее хранение предпочтений.

| Токен | HEX |
|---|---|
| `dark-canvas` | `#101B2A` |
| `dark-surface` | `#19283A` |
| `dark-surface-alt` | `#203349` |
| `dark-border` | `#3A4C60` |
| `dark-ink` | `#F0F4F8` |
| `dark-muted` | `#C1CCDA` |
| `dark-accent` | `#91B8FF` |
| `dark-accent-soft` | `#263E63` |

Сохранять классический синий `#124191` в **изображении логотипа на светлом фоне**, а в тёмном режиме для читаемости использовать белый вариант или адаптированный контрастный акцент. Не делать текст `#124191` на тёмной поверхности.

### CSS-контракт токенов

Новые семантические переменные должны стать одним источником истины. Существующие `--bg`, `--panel`, `--panel2`, `--border`, `--text`, `--muted`, `--blue`, `--radius` временно маппить на новые значения, не разрывая страницы.

## 4. Логотип и идентичность

- **Использовать уже имеющиеся** `symport/web_assets/brand/nokia-blue.svg`, `nokia-white.svg`, `nokia-symport-horizontal.svg`, `appmark.svg`. В `nokia-blue.svg` в текущем репозитории действительно прописан `#124191`.
- Воссоздавать и использовать именно цельные буквы классического wordmark (до 2023). Не набирать NOKIA обычным шрифтом: для него нужен векторный wordmark, не CSS `font-weight: 900`.
- Главный бренд пользовательского инструмента — **SymPort**; Nokia — исторический контекст и совместимость. В шапке можно использовать классическое слово NOKIA рядом с текстом `SymPort`, а ниже мелко `S60 DEVICE WORKSPACE` / `NOKIA E52 & E72`. Не объявлять себя официальным приложением Nokia.
- Бренд в desktop sidebar — единая строка/компактный lockup с общей высотой ~46–58 px; мобильная версия — меньше. Не делать огромный логотип, отнимающий рабочую область.
- Фавикон/PWA — локальный `brand/appmark.svg` с лаконичным бело-синим символом, не новая стилистика 2023.
- Исходные SVG и `graphics.json` не переписывать без причины: hash/provenance сохранять либо обновлять явно при переработке.
- Имеющиеся файлы — **независимые проектные изображения**, а не подтверждённые официальные ассеты Nokia. Уважать товарный знак, права на графику и не утверждать официального партнёрства.

## 5. Типографика

- Ориентир эпохи — **Nokia Sans**; **Nokia Pure** представлен в 2011 году, поэтому не использовать Pure как исторический дефолт E52/E72.
- Шрифты Nokia могут быть несвободными: **не скачивать и не включать Nokia Sans/Pure без права распространения**. Практический стек: `"Segoe UI", Tahoma, Arial, sans-serif` (с поддержкой кириллицы). Существующий Inter можно оставить временным резервным шрифтом, но убрать сильную «стартаповую» геометрию и отрицательный tracking заголовков.
- Заголовок страницы 26–30 px, 600–700; секция 17–20 px, 600; обычный текст 13–14 px, line-height 1.45–1.55; вторичные подписи 11–12 px. На мобильном увеличить элементы взаимодействия, а не уменьшать буквы до нечитаемых.
- Служебные данные, путь и коды: существующий `JetBrainsMono` / `FiraCode` только для технической информации, не для названий разделов.
- Убрать повсеместные uppercase-eyebrow, широкую разрядку, сверхкрупные marketing hero и `letter-spacing: -.035em`.
- Числа и размеры файлов отображать единообразно (`font-variant-numeric: tabular-nums`), без ложной точности.

## 6. Компоновка интерфейса

### Общая оболочка (desktop 1280–1920 px)

- **Sidebar:** 212–232 px; белый / очень светло-серый, граница справа 1 px; компактный логотип и вертикальные пункты с пиктограммами 18–20 px.
- Активный пункт: `brand-soft`, **полоса 3 px Nokia Blue слева**, насыщенный синий текст и иконка; hover — `surface-strong`. Не обводить каждый пункт отдельной огромной карточкой.
- **Topbar:** 52–58 px, чистый белый фон, тонкий разделитель, слева breadcrumbs, справа выбор устройства, статус подключения и RU/EN / Light/Dark. Никаких крупных маркетинговых бейджей.
- **Main:** фон `canvas`, боковые поля 24–32 px, внутренние панели белые, ширина рабочих областей зависит от задач. Нет обязательного `max-width` для файлового менеджера и таблиц, если это ограничивает работу.
- **Panels:** 1 px `border`, радиус 5–7 px, скромная тень или вовсе без неё; расстояния 12–16 px. Отдать приоритет информации перед декором.
- **Spacing:** базовая шкала 4 / 8 / 12 / 16 / 24 / 32 px; touch-цели >= 44×44 px на мобильном, focus ring обязателен.
- **Dashboard:** сверху статус телефона и его **реальная** иллюстрация, рядом подключение, модель/RM, батарея/память и доступные транспортные возможности; ниже компактные разделы «Файлы», «Контакты», «Сообщения», «Медиа», «Приложения», «Темы». Никаких выдуманных показателей или фейкового «Connected».

### Адаптивность

- `>=1200 px`: sidebar + полноразмерные таблицы/файловая двухпанельность.
- `761–1199 px`: узкая sidebar или сворачиваемая навигация, панели по содержимому.
- `<=760 px`: безопасно доступная мобильная навигация, кнопки >=44 px, одна колонка, панели/таблицы с **локальным** скроллом, не горизонтальный скролл всей страницы.
- Для E52/E72 из Emulator Lab сохранять **настоящие** пропорции 240×320 и 320×240, отдельно от адаптивности браузера.

## 7. Компоненты — однозначные правила

| Компонент | Nokia Classic |
|---|---|
| Primary Button | Сплошной `#124191`, белая подпись, радиус 5 px, 36–40 px desktop / >=44 px touch; hover `#0E3579`; disabled обоснован |
| Secondary Button | Белая поверхность, 1 px серый/сине-серый бордер, тёмный текст; hover серовато-голубой |
| Destructive Button | Красный только у реально опасных действий; отдельное подтверждение, не использовать для обычного «Отключить» без оценки последствий |
| Inputs/Selects | Компактные, ясные подписи, высота 36–40 px desktop; border 1 px, radius 4–5 px, синий focus ring, видимая ошибка |
| Cards/Panels | Белый, бордер, радиус 6–7 px; без глубокой тени и без декоративного свечения |
| Tabs | Подчёркивание/нижняя линия 2 px Nokia Blue или классические сегменты; полностью доступные состояния клавиатуры |
| Tables/Lists | Заголовок серый `surface-strong`; строки 36–44 px; тонкие линии, hover light blue, selected `brand-soft`; сортировка и действия очевидны |
| Tree/File Explorer | Папки/диски слева, содержимое справа на широких экранах; breadcrumbs, выделение, сортировка, множественный выбор, drag/drop только с проверкой поддержки |
| Dialog | Белый компактный модальный слой, 1 px border, ясный заголовок, действия внизу справа; достаточный контраст backdrop |
| Progress | Полоса `brand`; реальный прогресс или явное indeterminate состояние; never fake percentage |
| Status chips | Прямоугольные/слегка скруглённые (4 px), цвет + пиктограмма + текст; «Подключено», «Неизвестно», «Недоступно» не сводить к одному цветному кружку |
| Alerts | Нейтральный/голубой для информации, янтарный для предупреждения, красный для ошибки, зелёный для успеха; не использовать blue для всех ошибок |
| Icons | Простой исходный SVG, 18–20 px, толщина stroke ~1.8–2.2 px, единая геометрия, преимущественно `currentColor` |
| Empty states | Маленькая функциональная иллюстрация + одна конкретная следующая операция; без декоративной гигантомании |
| Loading | Не замораживать весь интерфейс без нужды; управлять disabled/busy и aria-live |

**Иконография:** сохранить/привести к одному виду текущие 18 `web_assets/icons/outline/*.svg` и `icons/tiles/*.svg`. Навигация по умолчанию монохромная; выборочные оригинальные цветные иконки (контакты, сообщения, музыка, календарь) допустимы как отсылка к Symbian, но это **новые собственные SVG**, а не скопированные бинарные иконки из прошивки. Не перекрашивать всё цианом. Иконка должна узнаваться без подписи, но подпись оставлять.

## 8. Проработка по разделам SymPort

| Раздел | Целевой вид и приоритет |
|---|---|
| **Обзор / Device Dashboard** | P0. Белая статусная панель с E52/E72, реальными параметрами и доступными действиями; не использовать тёмный огромный hero. Отличать `disconnected`, `unknown`, `connected`, `unsupported` |
| **Подключение / SymPort Bridge** | P0. Пошаговый desktop wizard в компактных плоских блоках, выделить pairing/разрешения/проверку; состояние Windows Bridge отдельно от физического USB/транспорта |
| **Файлы** | P0. Главный сценарий в духе PC Suite: tree + list, тип/размер/дата, путь, поиск, мультивыбор, загрузка/скачивание, подтверждение удаления; уважать capability matrix |
| **Медиа / Галерея** | P1. Сетка превью на светлой рабочей поверхности, компактные панели инструментов, в деталях честная метаинформация, поддержать крупный предпросмотр |
| **Контакты / SMS / Календарь** | P1. Плотные списки и таблицы, функциональные заголовки и состояния синхронизации; выделенные элементы синие, подтверждение импорта/записи обязательно |
| **Каталог приложений** | P1. Небольшие узнаваемые иконки Symbian/J2ME, сильная типографика названия/версии/совместимости, фильтры; не смешивать «скачано», «передано» и «установлено» |
| **Темы E52 CLEAR** | P1. Исторически уместная светлая галерея; два реальных превью телефона и тех. статус пакета; НЕ менять генерируемые `theme/src/*` темы без отдельной задачи |
| **Ringtone Studio** | P1. Строгий светлый audio editor; waveform/regions/плеер остаются выразительными и управляемыми, синий для выделенного участка, не потерять точность времени/mono/LUFS/fade |
| **Certificate Inspector** | P1. Инспектор как системная утилита: факты, подписи, capabilities, совместимость, риск/отказ, без ложного зелёного «сработает» |
| **Emulator Lab** | P2. Сдержанная управляющая панель вокруг реального устройства и экрана; сохранить клавиши и пропорции телефона, логи и предупреждения ROM/SDK; не выдавать mock за device proof |
| **Jailbreak Manager** | P2. Никакой эстетизации рискованных действий: явные границы эксперимента, предупреждения, staging/dry-run, доказательства, restore без обещаний гарантий |
| **Бэкапы / Окружение / Разработка** | P2. Плотные служебные таблицы, логи, прогресс, версия, hash; строгие статусы и читаемые code blocks |

## 9. План внедрения в реальный репозиторий

### Текущее состояние, которое агент обязан учитывать

- В репозитории **на момент написания** frontend — `symport/web_assets/index.html` + локальные JS (`app.js`, `manager.js`, `suite.js`, `connection.js`, `catalog.js`, `lab.js` и другие). **React + TypeScript пока не подтверждены в `main`**: не строить решение на несуществующих компонентах и package.json.
- Стили подключаются слоями: `app.css` → `compact.css` → `nimbus.css` → `lab.css` → `preferences.css`, плюс страничные `ringtone.css`, `device-workspace.css` и другие. Порядок каскада критичен: `nimbus.css` меняет цвета/скругления, а `preferences.css` задаёт dark mode.
- У текущего Nimbus фирменный акцент `#0E74E9`, cyan `#22D3EE`, панели radius 16 px; ранний `app.css` содержит зелёный `#059669`. Всё это **не должно просочиться в Nokia Classic** как цвета primary.
- В `symport/web_assets/brand/nokia-blue.svg` уже есть независимое векторное изображение с `#124191`; есть набор outline/tiles и источники в `graphics.json`.
- В `docs/UI_DESIGN.md` документирована Nimbus. Новый файл `design.md` — целевое руководство; по завершении миграции исправить `docs/UI_DESIGN.md` и README, чтобы они не противоречили реальному стилю.

### Этап A — Foundations (P0)

1. Внести CSS tokens и `Nokia Classic` в отдельный локальный `symport/web_assets/nokia-classic.css`. Подключить **после всех остальных локальных CSS**, включая page-specific стили. Правильно реализовать specificity/cascade; не полагаться на хаотичную лавину `!important`.
2. Перевести `body`, `.sidebar`, `.sidebar-panel`, `.brand`, `.topbar`, `.breadcrumbs`, `.content`, `.page-heading`, `.card`, `.btn`, `.nav-link`, `input/select/textarea`, `.chip`, `.status`, `a:focus-visible` на токены.
3. Сохранить исходные JS-события, идентификаторы элементов, `data-*`, fragment routing, RU/EN, `system/light/dark` и доступность; **не переименовывать DOM id без миграции тестов и обработчиков**.
4. Перевести lockup/logo в компактный вариант, не подменяя независимый SymPort официальным «Nokia PC Suite».
5. Убрать Nimbus как активную визуальную основу. После миграции удалить или изолировать неиспользуемые правила/стили; не хранить бесконечную цепочку конфликтующих override.

### Этап B — Main Workflows (P0–P1)

1. Обзор, подключение, файлы, модальные окна, таблицы, выбор устройства.
2. Контакты, SMS, календарь, медиа, каталог, темы.
3. Ringtone Studio: специальные waveform/regions/controls внутри исторической палитры, **без изменения аудио-алгоритмов**.
4. Inspector, Lab, Jailbreak, backup, development: их специальные компоненты привести к тем же токенам.

### Этап C — Icons, responsive, cleanup (P1–P2)

1. Нормализовать SVG в навигации и внутренних заголовках: stroke/currentColor, размеры, 18–20 px. Производить изменения источников целенаправленно и актуализировать файл provenance при необходимости.
2. Сделать адаптивное поведение на 390×844 / 768×1024 / 1440×900 / 1920×1080, без общего horizontal overflow.
3. Обновить скриншоты `docs/screenshots/*` (`node tools/capture_screenshots.cjs`) **только из реального работающего UI** (без фейковых данных и выдачи эмулятора за физический аппарат).
4. Уточнить и обновить `README.md`, `docs/UI_DESIGN.md` и любые тексты, где Nimbus указан как актуальная тема.
5. Не трогать API, транспортную безопасность, телефонные файлы, персональные данные, Docker volumes и серверные операции ради визуальной задачи.

### Если параллельно идёт миграция на React + TypeScript

Дизайн-система должна быть **framework-agnostic**: использовать те же CSS custom properties и атомарные правила. В React выносить `AppShell`, `Sidebar`, `Topbar`, `DeviceSummary`, `Panel`, `Button`, `StatusBadge`, `DataTable`, `FileExplorer`, `Dialog`, `Toast` без изменения семантики API. **Не делать React-миграцию предпосылкой для этого редизайна**. При одновременных работах не конфликтовать с агентом, выполняющим перенос фронтенда: согласовать файл-владелец и точку подключения новой темы.

## 10. Критерии приёмки

### Визуальные

- [ ] На всех экранах единый Nokia Classic, основной акцент `#124191` в light; нет активных Nimbus cyan/teal primary, «кошельковых» bento-секций и нецелевых радиусов 16+ px.
- [ ] Используется классический **сплошной** wordmark; нет графики ребрендинга 2023.
- [ ] Обзор/файлы/каталог/контакты/Ringtone Studio/Inspector/Lab связаны одной системой typography, spacing, icons, surface, states.
- [ ] Desktop напоминает аккуратную Nokia PC Suite эпохи E52, **но** работает как современный браузерный инструмент.
- [ ] Light — эталон, dark — читабельная вторичная тема, `system` работает корректно.

### Функциональные и доступность

- [ ] Для текста и контролов контраст WCAG AA (обычный текст >=4.5:1, крупный >=3:1; UI-индикаторы >=3:1), с индивидуальными исключениями только по стандарту.
- [ ] Visible focus, работа клавиатурой, `aria-*`, статусные live-регионы, disabled с объяснением, reduced-motion.
- [ ] RU/EN и длинные названия файлов/контактов/путей не ломают сетку; файлы и технические значения не транслитерируются дизайном.
- [ ] Ни одна операция не выдаёт «передано» за «установлено», «неизвестно» за «отключено», «сервер работает» за «подключён телефон».
- [ ] На 390×844 нет горизонтальной прокрутки **документа**; у широкой таблицы допускается внутренний overflow.
- [ ] Сохранены подтверждения записи/удаления/синхронизации, маскирование персональных данных и настоящее поведение транспортов.

### Реальные проверки проекта

Запускать подходящие существующие средства из `tools/`, в частности `check_web_ui.cjs`, `check_device_workspace.cjs`, `check_ringtone_ui.cjs`, `check_bridge_ui.cjs`, `check_emulator_lab.cjs`, `check_security_workspace.cjs`, а также существующий CI. Выбор окружения/запуска определить по инструкциям в репозитории; не объявлять тест пройденным без фактического выполнения.

Сделать сопоставимые **before/after** изображения как минимум для Dashboard, File Explorer, App Catalog, Ringtone Studio и Emulator Lab, для light/dark в desktop и light на 390 px. Проверить computed styles активной кнопки, фокуса, nav-item и selected-row. Не добавлять snapshot из фиктивных backend-данных без явной пометки test fixture.
